# 大模型上下文工程技术简报

- 一篇 C 级 CSDN 博客将上下文工程定义为管理“模型此刻能看到的全部信息构成”，动作含筛选、压缩、卸载、隔离、排序；并把提示词工程对应为单段提示词的措辞、示例、角色设定。——单一来源（C 级，作者自述，无 A/B 级交叉验证）
- 同文称压缩时保留最近 4 轮原文，使用同一模型并设 `max_tokens=400`；未说明样本、任务与统计口径，数值不可外推。——待核实（C 级）
- 另一 C 级博客摘要称 RAG 属于上下文工程，因 RAG 动态向窗口放入最相关信息；并称其管理“放什么、放多少、顺序、压缩、丢弃”。——单一来源（仅从摘要提取，未读正文）
- 一篇 C 级教程将 Prompt、Context、Harness、Loop、Graph 列为五大核心工程方法，称 Context 涉及上下文筛选。——单一来源（教程自述，无权威引用）

核验结论：现有材料无 A/B 级锚点，不足以支撑“统一行业定义”或“压缩参数为最佳实践”；相关结论待核实。缺官方文档、论文、开源 README/CHANGELOG 或带样本口径实验报告。
