# RAG 与长上下文的关系

**一句话定义**：RAG（检索增强生成）与长上下文是给大模型补充外部知识的两种路线：前者先检索再注入，后者直接扩大模型一次能读的文本量。

**为什么重要**：长上下文窗口变大后，很多人以为把文档全塞进去就够了，但成本、延迟和"中间信息被忽略"的问题依然存在。RAG 用按需检索替代全量输入，解决了知识更新和成本控制的痛点。

**怎么运作**：

- **RAG 链路**：文档切块—向量化入库—按查询召回相关片段—拼进提示词生成。知识留在外部库，模型每次只读相关的那部分。
- **长上下文路线**：把整份文档或大批材料直接放进窗口，靠注意力机制做全局比对，省去检索环节，代价是 token 消耗随输入线性上涨。
- **两者结合**：先用检索缩小范围，再把命中内容放进扩大的窗口做深度阅读，兼顾精度与全局理解。

**实践要点**：

- 知识频繁更新、库很大时优先用 RAG：改索引即可，不必重训模型。
- 需要跨文档全局对照（如条款逐条核对）时用长上下文，避免分块切断语义。
- 长上下文成本随 token 线性上涨，可先检索再喂入，控制单次输入量。
