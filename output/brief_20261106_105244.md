# MCP 的基本架构与适用场景

**一句话定义**
MCP（Model Context Protocol，模型上下文协议）是 Anthropic 推出的开源协议，用统一接口把大模型与外部数据源、工具连接起来。

**为什么重要**
过去每接一个工具都要单独写对接代码，N 个模型配 M 个工具就是 N×M 份工作。MCP 把这层收敛成标准接口：工具方写一次服务器，支持该协议的模型都能直接用。

**怎么运作**
- **角色分工**：服务器把能力分三类暴露——可执行动作的工具、可读取的数据资源、预设指令模板；客户端负责通信并转达模型的选择。
- **一次调用的链路**：用户提问 → 应用把可用工具清单交给模型 → 模型选定工具并生成参数 → 应用调用对应业务接口 → 结果回注上下文 → 模型据此作答。
- **分层结构**：协议层管请求格式、鉴权、加密与错误处理；适配层把 REST、WebSocket、gRPC 双向转换；编排层做条件分支与并行调度。

**实践要点**
- 隐私敏感或要完全离线的任务，让客户端直连本地工具，数据不出机器。
- 业务鉴权放在执行层自己做：MCP 只统一「怎么描述、怎么调用」，不接管权限校验，也替代不了既有鉴权体系。
- 接入不必重写全部 API：先挑一两个高频工具做成服务器验证收益，再逐步铺开。
