# MCP 的基本架构与适用场景

**一句话定义**：MCP 是让大模型通过标准接口访问外部数据与工具的开放协议，属 AI 应用集成领域，解决模型不知业务系统能力与调用方式的问题。

**为什么重要**：过去每接一个数据源或工具，都要为某个模型或应用单独写适配代码，重复且难维护。MCP 把能力统一成可发现的工具描述，让应用换模型或新增系统时少改代码。

**怎么运作**：
- **组件分工**：应用/客户端、模型、工具描述和外部系统协作；应用把能力描述成工具清单。
- **调用链路**：用户提问后，应用把问题与工具说明交给模型，模型选择工具并生成参数；应用调用业务 API 或数据源。
- **结果回注**：应用把结果作为上下文回注模型，模型据此组织答案。

**实践要点**：
- **先跑通单工具**：用一个高频查询封装 MCP 工具，验证“提问—选工具—调用—回注”链路再扩展。
- **权限放执行层**：模型只生成调用意图和参数，由应用校验权限、限制可访问数据与操作范围。
- **明确边界**：MCP 不替代业务 API，也不自动授予模型数据权限；接入数据库、文件系统或业务 API 时仍需原有鉴权与审计。
